# 1万時間チャレンジ：ホームページ公開準備メモ

ユーザーの指定により、アプリ紹介・共有利用条件・削除依頼ページと、共通プライバシーポリシー内の本アプリの説明は「公開準備中」として作成しています。プライバシーポリシーの本文は他のアプリと共通のページに統合しました。以下は担当者向けの作業メモであり、Web本文へ転載しません。アプリ側のFirebase接続や共有機能をサイトへ実装したものではありません。

## 用意したURL

- 共有機能の利用条件：https://simpleflowapps.com/10000hours/terms/
- プライバシーポリシー（Play Console等への登録用）：https://simpleflowapps.com/privacy/

- アカウント・通報データの削除依頼：https://simpleflowapps.com/10000hours/delete-account/

旧候補URL（/10000hours/privacy/）は共通ポリシーの本アプリの説明へ自動移動する案内ページです。新たなリンクには共通ページのURLを使用します。

これらはソースに用意した公開先です。この作業では本番へのデプロイや本番URLの疎通確認は行っていません。

## 正式公開前に運営者・開発担当者が確定すること

- contact@simpleflowapps.comで削除依頼を受信できること、受付担当、本人確認の方法。
- 本人確認後の処理目安と、遅延時の案内方法。
- 掲載終了後の投稿・通報・運営処理情報、匿名化した審査記録、問い合わせメールの保存期間と削除基準。期限を実際の管理処理と一致させること。
- 制定日・適用開始日。現在の「原案作成・最終更新日」は文書の準備日であり、正式な適用開始日ではありません。
- 公開版の広告ID取得有無、広告の種類、Google Mobile Ads SDK／Google UMPの設定と説明。
- Google Analytics for Firebaseを初版に含めるか。現時点では未実装・導入検討中としており、サイトにもAnalyticsタグは追加していません。導入する場合は、実際の計測項目・同意・停止方法・保持期間を反映すること。
- Firestoreの実際の地域。認証等を含むすべての情報が日本国内で処理されるという説明は加えていません。
- アプリ内リンク、Play Consoleのプライバシー／アカウント削除URL、データセーフティとの一致と、実機での共有接続確認。

配信済みカードの最大24時間の表示期限は、運営によるアカウント削除の対応日数ではありません。掲載週の終了とサーバー上のデータ削除も異なります。

## 後から差し替える箇所

- アイコン：index.htmlの「app-10000hours」カード内の画像src。現在はassets/images/10000hours-placeholder.svgを使用しています。正式画像を配置してsrcとwidth／heightを更新します。画像が見出しと重複する装飾であればaltは空のままにします。
- アプリ名・紹介文：index.htmlの同カード、および検索・SNS用description、operator/index.html。ストア掲載予定名は「1万時間チャレンジ - 習慣の記録」、Androidパッケージ名はcom.simpleflowapps.habittrackerです。
- ストアリンク：実際のGoogle Play掲載ページを確認後、カードに追加します。現時点ではリンクを設けていません。
- 共有の紹介文：提供開始と実機確認後に「時間の節目に到達したときは、カテゴリ・節目・達成日時だけを共有できます。」を追加できます。CSV復元、クラウドへの日々の記録同期、SNS自動投稿の説明は加えません。

## 正式公開の仕上げ

1. 未確定事項を反映し、共有利用条件・削除依頼ページと共通プライバシーポリシー内の「1万時間チャレンジ」の案内・制定日・適用開始日を更新します。共通プライバシーポリシーの保存期間・削除の説明と削除依頼ページを一致させます。
2. 共有利用条件・削除依頼の個別2ページのrobotsメタタグ「noindex, follow」を除去し、sitemap.xmlへ2つのURLと実際の更新日を追加します。共通プライバシーポリシーは既存の公開ページとして検索対象を維持しています。旧プライバシーURLの移転案内はnoindexとし、サイトマップへ追加しません。
3. 外部送信表の該当サービスを実際の提供状況に合わせて「利用中」へ変更し、共通ポリシーと運営者情報も更新します。
4. ログインなし・スマートフォンのブラウザで、共通プライバシーポリシーと個別2ページの関連リンク、旧URLからの移動、件名付きmailto、メールを使った依頼方法を確認します。
5. ホームページをデプロイし、HTTPSの公開URLが正常応答することを確認後、アプリ開発担当者にURL・適用開始日・確定した処理目安と保存期間・受信確認済みの問い合わせ先を共有します。
